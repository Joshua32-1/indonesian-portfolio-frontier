# IDX Portfolio Tracker — Live Dashboard

Minimal Vercel-hosted dashboard showing **indexed performance** of a **methodology matrix × κ** (300 streams = 10 configs × 6 variants × 5 κ) against IHSG, plus latest portfolio weights. The 6 variants are Max Sharpe, Min Variance, Tail λ=0.10/0.20/0.35/0.50; the 10 configs are `pert` (legacy PERT) + Black-Litterman × prior{cap,shrunk,equal} × τ{0.01,0.03,0.10}; κ ∈ {0,0.1,0.25,0.5,0.75} is a post-hoc turnover penalty.

**Methodology / Prior / τ / κ / Frequency / Cost** selectors slice the matrix. Rebalance **frequency** (weekly/monthly/quarterly) and **gross/net-of-cost** are **derived in-browser** (not stored): net-of-cost uses a liquidity-aware trailing-63 ADV model (`src/math/transactionCosts.js`) fed by the snapshot's `dollarVol`.

## Stack

- Vite + React (static SPA — no backend)
- Recharts for charting
- Data: `data/live-market-snapshot.json` (auto-refreshed by CI) + `data/portfolios.json` (you maintain)

## Vercel deploy

1. Push this repo to GitHub.
2. Create a new Vercel project → **Import** → select this repo.
3. Set **Root Directory** to `live-dashboard-portfolio`.
4. **Build command:** `npm run build`  **Output directory:** `dist`  **Install:** `npm ci`
5. Deploy — done. No environment variables needed.

## Weekly workflow

Rebalances are normally **automated** — the weekly `weekly-rebalance.yml` Action runs the optimizer per config (all 10, `optimize.mjs --emit`), then `merge-rebalances.mjs` assembles the κ=0 streams **and synthesizes the κ>0 (`-k<KK>`) variants** (post-hoc blend toward drift), and **commits directly to `main`** — the push auto-redeploys this dashboard (no PR gate; the merge script fails the job rather than pushing malformed weights). See [FORWARD-TEST.md](../FORWARD-TEST.md).

### Manual append (per stream)

Manual appends target the **κ=0** streams only; κ>0 rows are derived by `merge-rebalances.mjs`. To append by hand, add a rebalance row to the matching κ=0 **stream** (`<base>@<configTag>`) — do NOT overwrite old rows:

```json
{
  "effective": "2026-07-01",
  "weights": { "BBCA": 0.15, "BBRI": 0.12, "...": 0.0 }
}
```

Then update `"updated"` at the top of `portfolios.json`, commit, and push → Vercel auto-redeploys.

> Weights are **fractions** (0.15 = 15%). All weights in a rebalance entry must sum to approximately 1.00. The TOTAL row in the dashboard turns red if the sum is off.

## Price refresh (automatic)

A GitHub Action (`.github/workflows/refresh-dashboard.yml`) runs on weekdays at 11:00 UTC (18:00 WIB — after IDX close) to:

1. Run `npm run fetch-snapshot` inside `live-dashboard-portfolio`.
2. Commit and push the updated snapshot if changed → Vercel redeploys.

The fetch script is self-contained in this folder. It uses `yahoo-finance2` `chart()` (not `historical()`) to avoid errors on unsettled recent bars, and drops any bar where `adjclose` is null. Yahoo typically lags 1–2 trading sessions before finalized adj closes are available. Each bar also carries **`dollarVol`** (raw close × volume, IDR) so the dashboard can compute the net-of-cost overlay.

To run locally:

```bash
cd live-dashboard-portfolio
npm run fetch-snapshot
npm run dev
```

## Stitched history

The chart **never resets** when you add a new rebalance. The index compounds continuously from `inception`:

- Each daily bar: `index_t = index_{t-1} × exp(Σ w_i(t) · r_i,t)`
- `w_i(t)` = the weight active on or before that bar's date
- Weekends and IDX holidays have no bar — the next trading day's return spans the full gap
- Adding a new `effective` row only changes the **future slope** of the line; past values are identical

## Matrix skeleton

The 300-stream skeleton (10 configs × 6 variants × 5 κ) is generated by [`scripts/init-portfolios-matrix.mjs`](scripts/init-portfolios-matrix.mjs) (it refuses to run once any stream has rebalance rows, so it never wipes seeded weights). The axes live in [`scripts/lib/kappaExpand.mjs`](scripts/lib/kappaExpand.mjs). To add the κ>0 streams to an **already-seeded** file without wiping history, use [`scripts/add-kappa-streams.mjs`](scripts/add-kappa-streams.mjs) (additive) then [`scripts/backseed-kappa.mjs`](scripts/backseed-kappa.mjs) (one-shot history seed). Don't add/remove streams by hand mid-test. Colours are keyed by the stream **base** id in `src/App.jsx` (priors and κ variants share a base colour).

## `portfolios.json` format

```json
{
  "inception": "2026-06-30",
  "updated": "2026-06-30",
  "riskFreeRate": 0.0575,
  "portfolios": [
    {
      "id": "max-sharpe@bl-cap-t03",
      "base": "max-sharpe",
      "methodology": "bl",
      "prior": "cap",
      "tau": 0.03,
      "kappa": 0,
      "label": "Max Sharpe (Consensus)",
      "rebalances": [
        { "effective": "2026-06-30", "weights": { "BBCA": 0.14, "...": 0.0 } },
        { "effective": "2026-07-07", "weights": { "BBCA": 0.12, "...": 0.0 } }
      ]
    }
  ]
}
```

Stream `id` is `<base>@<configTag>` for κ=0 (unchanged) or `<base>@<configTag>-k<KK>` for κ>0 (`KK = round(κ·100)`); configTag = `pert` or `bl-<prior>-t<NN>` (`NN = round(τ·100)`). For `pert`, `prior` and `tau` are `null`; `kappa` ∈ {0,0.1,0.25,0.5,0.75} (absent ⇒ 0 on the pre-κ streams). Tickers must match exactly those in `live-market-snapshot.json` assets (e.g. `BBCA`, not `BBCA.JK`). See [API.md](../API.md#2-portfoliosjson) for the full contract.
